## 공용 파일
- `LOG.md` — 모든 팀이 끝날 때 한 줄씩(최신이 위): `YYYY-MM-DD HH:MM | 팀 | 한 것 | 다음/막힌 것`
- `PRIORITIES.md` — 실무이사가 매일 밤 쓰는 내일 우선순위. 모든 팀은 시작할 때 읽는다.
- `research/YYYY-MM-DD.md` — 리서치팀 산출물(출처 링크 필수).
- `../marketing/daily/YYYY-MM-DD/` — 마케팅팀 산출물.

## 공통 규칙 (ROADMAP 운영 원칙이 우선)
- 가격·약관·환불·결제(PAY/BANK)·멤버십(키, members.json, #/m/)·android/ 설정은 세준 요청 없이 바꾸지 않는다. 비밀값·키·남의 개인정보(테스터 이메일 등)를 저장소에 올리지 않는다.
- 앱 모드(?src=twa)에는 가격·결제·계좌·외부 홍보 배너를 보이지 않는다.
- 지어낸 사실·수치·후기 금지. 저작권 남은 작품 이미지 금지(작가 사후 70년).
- 메인 히어로는 고전·현대·동서양 교차, 반 고흐·모나리자 같은 뻔한 작품 제외.
- 나눔 표기: "도움이 필요한 가정과 사랑스런 아이들"(이 철자). 지역 표현·금액 숫자 금지.
- SNS·블로그 공개 게시, 메일 발송, 광고 계정 변경, 결제, 약관 동의는 하지 않는다(초안까지).

## 해설 규칙 — 3분 해설 + 도슨트 카메라 (세준 지시 2026-11-02)
세준: "작품을 볼 때 사진 하나만 띄우지 말고, 미술관에서 보듯 천천히 줌인하고 옆으로 지나가고 다른 각도에서 보면서 면밀하게 살펴보게. 해설은 작품마다 3분 정도로."
- 모든 작품의 `text.ko`/`text.en`은 약 3분 분량이다(ko 1,000~1,150자, en 2,300~2,700자). 예전 짧은 해설은 `short`에 남아 있다.
- 감상 모드 카메라 동선은 `tour`가 정한다: `[{x,y,z,t,ko,en}]` — x·y는 작품 안 위치(0~1), z는 배율(1=전체, 디테일 1.6~2.8), t는 기울기(도, 작품당 1~2곳만), ko/en은 그 단락이 시작하는 문장 번호.
- **새 작품을 넣을 때(콘텐츠팀)**: 해설을 단락 9~12개로 쓰고 단락마다 카메라 위치를 정해 `data/tour-src/<id>.json`(`{"id","segs":[{"ko","en","x","y","z","tilt"}]}`)에 저장 → `python3 scripts/tour.py data/tour-src` 로 works.json에 반영(검사만은 `--check`). 좌표는 반드시 작품 이미지를 직접 보고 정한다(10% 격자를 그려 확인). 첫 단락 z=1(작품 전체), 마지막 단락 z≈1(한 걸음 물러나기).
- 내용 흐름: 첫인상 → 화가·제작 배경 → 부분별 읽기(카메라가 실제로 이동하는 핵심) → 기법·재료 → 시대·평가 → 감상 질문 하나. 기존 사실·`look`·`words`는 모두 살린다. 사실은 미술관·위키 원문으로 확인한 것만.
- ko는 TTS가 읽으므로 괄호·영어 병기·특수기호를 쓰지 않는다(작품명은 '…'). 한 문장 70자 이내.
- 음성은 works.json push 시 narration.yml이 16대로 나눠 4가지 목소리를 만든다(약 1시간).
- 품질검수팀은 새 작품의 tour 좌표가 말하는 대상과 맞는지(이미지와 대조)도 본다.
